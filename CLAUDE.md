# hack-14

A single Next.js 16 app (App Router, Turbopack). No accounts, no database: the
app is open to anyone with the link. It has the you.com client, cache, Luma
participant lookup (public, or the full guest list with the user's Luma login),
enrichment and client-side filters. Recommendations aren't built yet. See
`readme.md` for setup, the Luma flows and the roadmap.

## This is NOT the Next.js you know

Next 16 has breaking changes — APIs, conventions, and file structure may all
differ from your training data. Read the relevant guide in
`node_modules/next/dist/docs/` before writing any code. Heed deprecation notices.

Specifically:

- `cookies()` from `next/headers` is **async** — always `await` it.
- `cookies().set()` / `.delete()` only work inside route handlers and server
  actions, not in server components.
- `next dev` regenerates `AGENTS.md` at the repo root. It's gitignored; don't
  commit it, and don't move its content here by hand.

## Layout

```
app/
  page.tsx                     the home page: header + event lookup
  event-lookup.tsx             Luma link input, enrichment, stars, filtered list (client component)
  luma-connect.tsx             connect / disconnect the user's Luma login (paste the cookie) (client component)
  people-filters.tsx           tabs, search, role/industry chips, sort (client component)
  person-card.tsx              one participant card: details, tags, star (client component)
  lib/types.ts                 shared types: Participant, EventParticipants, Enrichment, LumaConnection
  lib/api.ts                   client-side fetch helpers (event participants, enrichment, Luma connect)
  lib/classify.ts              role/industry tags + seniority from profile text (client-safe, pure)
  lib/env.ts                   env vars, read lazily
  lib/you.ts                   you.com Search + Contents client
  lib/cache.ts                 query-keyed in-memory cache; every you.com call goes through it
  lib/luma.ts                  event link → participants: public (you.com + __NEXT_DATA__) or full guest list
  lib/luma-api.ts              api.luma.com client, authenticated with the user's Luma login
  lib/luma-session.ts          encrypted HttpOnly cookie holding that login
  lib/enrich.ts                participant → find LinkedIn (Search), read LinkedIn/X/website (Contents)
  api/luma/{participants,enrich,connect}/route.ts
```

## Conventions

- Env vars are read through **getter functions** in `app/lib/env.ts`, never at
  module scope. `next build` evaluates route modules, so a missing variable must
  break a *request*, not the build.
- `app/lib/{env,you,cache,luma,luma-api,luma-session,enrich}.ts` are server-only
  (`import "server-only"`). Never import them from a client component; the
  client uses `app/lib/api.ts`.
- Outbound you.com calls go through `cached()` in `app/lib/cache.ts`, keyed on
  the query (never the user). They're metered — don't bypass the cache.
- Routes are same-origin, so client fetches need no `credentials: "include"`
  and there is no CORS config.
- There is no sign-in, so every route is public and every you.com call it
  makes is paid for by our key. Keep calls behind the cache, and never add a
  route that searches or fetches arbitrary client-supplied input.
- The user's Luma login (`luma.auth-session-key`) is a full account
  credential. It lives only in the encrypted `luma_session` cookie
  (`app/lib/luma-session.ts`), is sent only to api.luma.com (never to you.com),
  and must never be logged, returned to the browser, or put in an error.
- Don't sign in to Luma from the server: Luma requires a browser-only
  Turnstile check, and getting around it is off the table.
- Routes that call you.com or Luma set `export const maxDuration = 60` so
  Vercel doesn't cut them off.
- Data fetched with someone's Luma login is theirs: cache it keyed on their
  Luma user id, never in a shared key.
- Avoid `next/font/google`: it fetches at build time, which fails in restricted
  network environments. The app uses a system font stack.

## Checks before calling anything done

```bash
npx tsc --noEmit
npx eslint .
npm run build
```

If npm fails with an `EPERM … _cacache` "root-owned files" error, the cache
path isn't writable — prefix the command with
`npm_config_cache="$TMPDIR/npm-cache"`.

## Secrets

Real credentials live only in `.env.local`, which is gitignored. Never read,
print, or commit it. `.env.example` carries placeholders only. `SESSION_SECRET`
(encrypts the stored Luma login) is generated by the user (`openssl rand -hex 32`).
